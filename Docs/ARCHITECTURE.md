# Архитектура Lang Switcher

Документ описывает фактически реализованную архитектуру версии 0.1.x. Приложение является нативным menu bar process для Apple Silicon и macOS 15+.

## Цели архитектуры

- исправлять текст непосредственно в активном приложении;
- не читать содержимое текстового поля целиком;
- не использовать clipboard;
- не терять ввод, пришедший одновременно с коррекцией;
- отключаться в защищённом контексте;
- не иметь обязательных серверов или сторонних runtime-зависимостей;
- позволить добавлять языковые пары без переписывания event monitor.

## Общая схема

```text
CGEventTap
    │ InputEventSnapshot
    ▼
InputCoordinator ──────────────── AppPolicy / AppSettings
    │
    ├── TypingStateMachine
    │       │ CompletedToken + TokenVariant
    │       ▼
    ├── LayoutCatalog ─────────── TIS / UCKeyTranslate
    │       │ current + alternate rendering
    │       ▼
    ├── DetectionEngine ───────── LocalLexicon / NSSpellChecker / Transliterator
    │       │ CorrectionProposal
    │       ▼
    └── CorrectionCoordinator ─── InputEventTap gate / EventSynthesizer / TIS

GlobalHotkeyManager ─────────────┘
AccessibilityTextService ──────── selected-text flow
```

## Запуск и жизненный цикл

Точка входа — `Main.swift`. Она поддерживает два режима:

- обычный GUI-процесс с `NSApplication` и `AppDelegate`;
- автономный `--self-test`, который не запускает UI и возвращает ненулевой exit code при ошибке.

`AppDelegate` создаёт сервисы и связывает их callback-ами:

1. загружает `AppSettings`;
2. перечисляет доступные раскладки через `LayoutCatalog`;
3. создаёт детектор, корректор и Accessibility-сервис;
4. регистрирует Carbon hotkeys;
5. создаёт menu bar и окно настроек;
6. запускает `InputEventTap`, если приложение включено;
7. сбрасывает контекст при смене frontmost application;
8. обновляет список раскладок при системном уведомлении об изменении input sources.

UI, TIS, Accessibility и принятие решений выполняются на `MainActor`. Callback event tap работает на отдельном run loop и не выполняет тяжёлых операций.

## Слой глобального ввода

### InputEventTap

`InputEventTap` создаёт активный `CGEventTap` уровня session в `headInsertEventTap`. Он наблюдает:

- `keyDown` и `keyUp`;
- `flagsChanged`;
- нажатия кнопок мыши;
- события отключения event tap системой.

Обычное событие немедленно пропускается дальше. На main queue передаётся только компактный `InputEventSnapshot`: тип, key code, flags, repeat-флаг и monotonic timestamp.

Синтетические события помечаются числом `langSwitcherEventMarker` в `eventSourceUserData`. Callback пропускает их, но не отправляет обратно в анализатор. Это предотвращает рекурсивные коррекции.

Если macOS отключает tap по timeout или user input, сервис повторно включает его и пишет обезличенное диагностическое событие.

### Correction gate

Во время короткой коррекции tap переходит в gating-состояние. Реальные `keyDown`, `keyUp` и `flagsChanged` не отправляются целевому приложению сразу, а складываются в память. После исправления они воспроизводятся порциями в исходном порядке.

Gate закрывается атомарно только после опустошения очереди. Если во время воспроизведения приходит ещё одно реальное событие, оно попадает в следующую порцию. Это защищает порядок ввода на границе транзакции.

## Модель набираемого слова

`TypingStateMachine` хранит:

- физические клавиши текущего токена;
- возможную неоднозначную последнюю пунктуационную клавишу;
- последнее завершённое слово;
- frontmost process и bundle identifier;
- monotonic время завершения.

Вместо сохранения только видимых букв хранятся `PhysicalKey`: key code, Shift и Caps Lock. Одинаковую последовательность можно отобразить в обеих раскладках.

Состояние сбрасывается при:

- клике мышью;
- смене приложения;
- Enter, Tab, Escape, стрелках, Home/End, Forward Delete;
- обычном Command/Control/Option shortcut;
- неизвестной или неподдерживаемой раскладке;
- Secure Input или защищённом поле.

Backspace удаляет последнюю физическую клавишу. После одного простого разделителя он может повторно открыть недавно завершённое слово. Сложная граница вроде `. ` не открывается, потому что положение курсора уже нельзя доказать безопасно.

### Неоднозначная пунктуация

Некоторые физические клавиши являются знаком препинания в English и буквой в Russian. Например, видимый знак может оказаться последней русской буквой, набранной в неправильной раскладке.

State machine временно сохраняет такую клавишу как ambiguous и рассматривает две версии:

1. клавиша является пунктуационной границей;
2. клавиша входит в исправляемое слово другой раскладки.

Если следующего события нет, вариант с пунктуационной границей завершается через 160 мс. Если приходит пробел, оба варианта передаются детектору, а удаляемая длина остаётся одинаковой.

## Раскладки

`LayoutCatalog` перечисляет keyboard layout input sources через Text Input Source Services. Input methods без `UCKeyboardLayout` исключаются.

Для каждого English/Russian source строится неизменяемый `KeyboardLayoutSnapshot`:

- `PhysicalKey → String` для key codes 0…127;
- комбинации обычного состояния, Shift, Caps Lock и Shift+Caps Lock;
- обратная карта `Character → PhysicalKey` для преобразования выделения.

Перевод выполняется через `UCKeyTranslate`. Карта не привязана к захардкоженному QWERTY/ЙЦУКЕН и пересобирается при изменении установленных input sources.

В настройках выбирается одна English и одна Russian раскладка. Автоматическое слово обрабатывается только тогда, когда текущий input source является одной из выбранных раскладок.

При переключении `TISSelectInputSource` результат проверяется опросом текущего source в течение максимум 80 мс. До подтверждения исходный текст не удаляется.

## Детектор

`DetectionEngine` получает две строки, построенные из одной физической последовательности:

- `current` — результат в активной раскладке;
- `alternate` — результат в другой раскладке.

Перед оценкой применяются жёсткие guards:

- password manager или исключённый bundle identifier;
- пользовательское «никогда не исправлять»;
- URL, email, путь, `snake_case`, `camelCase`, буквы вместе с цифрами;
- известные технические слова в строгом IDE-профиле.

Итоговый score складывается из:

- точного совпадения со встроенным common/extended lexicon;
- результата локального `NSSpellChecker`;
- доли символов требуемого алфавита;
- наличия гласных и штрафов за неправдоподобные кластеры;
- частых bigram/trigram;
- пользовательского правила «всегда исправлять».

Автозамена требует минимального score целевого варианта и достаточного отрыва от исходного. Порог зависит от выбранной агрессивности. Для слова длиной до двух символов и для IDE необходимый отрыв увеличивается.

### Фонетический транслит

Если переключение раскладки не принято, English source может пройти отдельный `Transliterator`. Он:

- обрабатывает только ASCII-токен;
- строит до 64 кандидатов;
- поддерживает сочетания `shch`, `zh`, `kh`, `ts`, `ch`, `sh`, `yo`, `yu`, `ya` и варианты одиночных букв;
- сохраняет исходный регистр;
- ранжирует результат тем же Russian detector.

Смешанные токены вроде `приvet` отклоняются: это отдельная backlog-функция.

## Транзакция коррекции

`CorrectionCoordinator` выполняет следующую последовательность:

1. сверяет frontmost PID с PID завершённого слова;
2. проверяет `IsSecureEventInputEnabled` и hard deny policy;
3. включает correction gate;
4. ждёт отпускания Command, Control, Option и Shift не более 350 мс;
5. выбирает целевую раскладку и подтверждает переключение;
6. выдерживает 12 мс для стабилизации input source;
7. посылает необходимое число Backspace;
8. для layout correction воспроизводит исходные физические клавиши в новой раскладке;
9. для фонетического транслита вводит готовый Unicode-текст;
10. отдельно возвращает точную строку разделителя;
11. дренирует накопленные пользовательские события и закрывает gate.

Unicode передаётся блоками максимум по 20 UTF-16 code units. Surrogate pair никогда не разделяется между блоками. У каждого synthetic event очищаются нежелательные flags и выставляется marker.

Если выбор раскладки не подтверждён, удаление не начинается. Если транзакция завершилась ошибкой после переключения, сервис пытается вернуть исходную раскладку.

### Отмена

После успешной коррекции в RAM хранится краткая запись исходного/нового текста, разделителя, PID и layout IDs. Повторный ручной хоткей в том же приложении в течение восьми секунд возвращает исходное слово. Любой последующий обычный ввод, клик или смена приложения уничтожает undo-запись.

## Преобразование выделения

Путь выделенного текста не связан с clipboard:

1. `AccessibilityTextService` получает focused AX element;
2. проверяет secure subrole;
3. читает `kAXSelectedTextAttribute`;
4. `SelectedTextConverter` выбирает направление по преобладающему Latin/Cyrillic script;
5. символы преобразуются через обратную карту физической раскладки;
6. если AX-атрибут settable, результат записывается непосредственно;
7. иначе оставшееся выделение заменяется Unicode-инъекцией;
8. целевая раскладка остаётся активной для последующего ввода.

Если приложение не публикует выделение через Accessibility и Unicode fallback невозможен, показывается локальное сообщение. Clipboard fallback намеренно отсутствует.

## UI и системные сервисы

- `StatusBarController` — menu bar и быстрые действия.
- `SettingsView` — SwiftUI-формы поверх `NSHostingController`.
- `FeedbackPresenter` — неактивирующий `NSPanel` и системный звук.
- `GlobalHotkeyManager` — Carbon `RegisterEventHotKey`.
- `PermissionManager` — проверка и запрос Input Monitoring/Accessibility.
- `LaunchAtLoginController` — `SMAppService.mainApp`.
- `DiagnosticLogger` — строго типизированные события Unified Logging без текста.

`AppSettings` использует `ObservableObject`, `@Published` и `UserDefaults`. Изменения публикуются через внутреннее notification, после чего AppDelegate обновляет hotkeys, menu bar и event tap.

## Границы модулей

- `Input` не знает о SwiftUI и формате словарных файлов.
- `Layout` не принимает решения о корректности слова.
- `Detection` не посылает события клавиатуры.
- `Correction` не читает AX-выделение и не хранит пользовательские настройки.
- `Accessibility` не использует clipboard и не знает о hotkeys.
- `UI` вызывает coordinators, но не содержит алгоритмов исправления.

## Расширение на другие языки

Модель `LanguageCode` сейчас содержит только EN/RU, но input pipeline работает с `KeyboardLayoutSnapshot`. Для новой пары потребуются:

1. новый language profile и выбор source в UI;
2. локальный lexicon и n-gram profile;
3. script coverage;
4. тестовый корпус;
5. при необходимости собственный transliterator.

Event tap, state machine, correction gate, Accessibility и Unicode emitter менять не требуется.
