# Руководство пользователя

## Назначение

Lang Switcher исправляет текст, набранный в неправильной English/Russian раскладке, непосредственно в браузере, мессенджере, офисном приложении или редакторе кода. Всё распознавание выполняется локально.

Примеры:

- `ghbdtn ` → `привет `;
- `руддщ ` → `hello `;
- при включённом транслите `privet ` → `привет `.

## Системные требования

- Mac с Apple Silicon;
- macOS 15 или новее;
- включённые в системе English и стандартная Russian раскладки;
- Accessibility и Input Monitoring.

Intel и macOS ниже 15 не поддерживаются.

## Установка локальной сборки

1. Открыть `dist/Lang-Switcher-0.1.0-arm64.dmg`.
2. Перетащить `Lang Switcher.app` в `Applications`.
3. Открыть приложение.
4. Если Gatekeeper блокирует ad-hoc сборку, открыть **System Settings → Privacy & Security** и выбрать **Open Anyway**.
5. В появившемся окне настроек запросить Accessibility и Input Monitoring.
6. После выдачи Input Monitoring полностью завершить и снова открыть приложение.

Lang Switcher не имеет Dock-иконки. После запуска появляется `AЯ` в menu bar.

## Первый запуск

На вкладке «Приватность» находятся два индикатора:

- зелёный — разрешение действует;
- оранжевый — разрешение ещё не выдано или требует перезапуска.

Кнопка «Обновить состояние и перезапустить монитор» повторно проверяет TCC и пересоздаёт event tap.

Проверка после настройки:

1. выбрать English раскладку;
2. открыть Notes;
3. набрать `ghbdtn `;
4. ожидать `привет `, сигнал и активную Russian раскладку.

## Menu bar

### Lang Switcher включён

Главный переключатель. При выключении event tap останавливается, буфер слова и undo очищаются. Настройки и menu bar остаются доступны.

### Автоисправление

Разрешает автоматическое решение на границе слова. Ручной хоткей продолжает работать, если главное приложение включено.

### Фонетический транслит

Включает отдельный путь `privet → привет`. Исправление неправильной раскладки `ghbdtn → привет` от этой настройки не зависит.

### Исправить последнее слово

Запускает то же действие, что базовый глобальный хоткей. Детектор не применяется: слово принудительно переводится в другую выбранную раскладку.

### Преобразовать выделение

Читает текущее выделение через Accessibility, определяет преобладающий алфавит и преобразует его. Clipboard не используется.

### Настройки и завершение

Открывают окно настроек или полностью завершают процесс.

## Автоматическое исправление

Приложение отслеживает физические клавиши текущего слова, но не читает весь документ. После пробела или пунктуации строятся версии слова в обеих раскладках.

Замена происходит, если:

- текущая раскладка входит в выбранную пару;
- альтернативный вариант существует;
- локальный detector считает его достаточно более вероятным;
- активное приложение и курсор не изменились;
- поле не защищено;
- слово не попадает под исключения и структурные guards.

После коррекции целевая раскладка остаётся включённой.

Пробел обрабатывается сразу. Пунктуационная клавиша, которая может быть буквой другой раскладки, ожидает до 160 мс или до следующего символа. Enter и Tab не запускают автокоррекцию, поскольку могут отправить сообщение или изменить фокус.

## Ручное исправление последнего слова

Ручной кандидат доступен примерно 12 секунд после завершения слова и только в том же приложении. Функция полезна, если:

- автоисправление выключено;
- detector оставил неоднозначное слово;
- используется IDE со строгим профилем.

Ручной путь не проверяет словарь: он принудительно воспроизводит физические клавиши в другой выбранной раскладке.

### Отмена

Если последнее действие было коррекцией, повторный ручной хоткей в течение восьми секунд возвращает исходный вариант. Undo отменяется при следующем обычном вводе, клике мышью или смене приложения.

## Преобразование выделенного текста

1. Выделить текст в редактируемом поле.
2. Нажать derived hotkey выделения или выбрать команду в menu bar.
3. Lang Switcher считает количество латинских и кириллических символов.
4. Выберет направление по преобладающему алфавиту.
5. Заменит символы согласно физическим картам выбранных раскладок.

Приложение сначала пытается записать `kAXSelectedTextAttribute`. Если приложение не разрешает AX-запись, используется Unicode keyboard injection поверх сохранившегося выделения. Если оба пути недоступны, показывается локальное сообщение, а clipboard остаётся неизменным.

В текущей версии направление выбирается для выделения целиком. Интеллектуальная коррекция отдельных смешанных слов находится в backlog.

## Фонетический транслит

Транслит предназначен для латинского произношения русских слов:

- `privet` → `привет`;
- `spasibo` → `спасибо`;
- `zh`, `kh`, `ch`, `sh`, `shch`, `yo`, `yu`, `ya` распознаются как сочетания.

Функция срабатывает только если исходное English-слово выглядит неизвестным, а Russian-кандидат получает достаточный локальный score. Из-за неоднозначности она имеет отдельный переключатель.

## Настройки

### Основные

- **Lang Switcher включён** — master switch.
- **Автоматически исправлять последнее слово** — автоматический detector.
- **Преобразовывать выделенный текст** — разрешает AX-команду выделения.
- **Звуковой сигнал** — системный `Tink` после успешной операции.
- **Визуальный сигнал** — краткий неактивирующий overlay.
- **Последнее слово** — выбирает пресет базового хоткея.
- **Запускать при входе** — регистрирует main app через `SMAppService`.

Доступные базовые пресеты:

| Исправить слово | Преобразовать выделение |
|---|---|
| `⌥Space` | `⌘⌥Space` |
| `⌃⌥Space` | `⌘⌃⌥Space` |
| `⌃⇧Space` | `⌘⌃⇧Space` |
| `⌘⌥Space` | `⌘⌃⌥Space` |

По умолчанию используется `⌃⌥Space`.

### Языки

Выбираются один English и один Russian keyboard layout из установленных системных источников. Для Russian предпочтительна стандартная раскладка, не Phonetic.

Если нужной раскладки нет, добавить её в **System Settings → Keyboard → Text Input → Edit**, затем нажать «Обновить раскладки».

### Распознавание

Режимы:

- **Осторожно** — максимальный порог, меньше замен неизвестных слов;
- **Сбалансированно** — средний порог;
- **Максимальное покрытие** — минимальный допустимый отрыв, режим по умолчанию.

«Всегда исправлять» принимает исходное ошибочное слово, по одному на строку. Для него dictionary decision обходится.

«Никогда не исправлять» принимает исходное слово, которое следует оставлять без изменений. Сравнение выполняется без учёта регистра.

### Приложения

**Строгий профиль для кода** повышает порог в IDE и защищает URL, пути, технические идентификаторы и распространённые code tokens. Xcode, VS Code и JetBrains не выключаются полностью: ручное исправление остаётся доступным.

В «Исключённые bundle identifiers» можно добавить приложения, где Lang Switcher не должен обрабатывать ввод. По одному identifier на строку, например `com.example.Editor`.

Password managers исключены встроенным hard deny и не могут быть включены этим экраном.

### Приватность

Показывает состояния Accessibility/Input Monitoring, открывает соответствующие System Settings и включает только обезличенные локальные диагностические события.

## Поведение в IDE

Строгий профиль пропускает:

- URL, email и пути;
- `snake_case`;
- `camelCase`;
- сочетания букв и цифр;
- известные технические токены вроде `swift`, `json`, `kubectl`, `nginx`.

Общий Accessibility API не позволяет надёжно различать код, комментарий и строковый literal. Поэтому неизвестное слово в комментарии иногда потребует ручного хоткея. Полное context awareness потребует editor plugin.

## Обратная связь

После успешной операции overlay показывает направление `English → Русский` или обратное. Звук и overlay отключаются независимо.

Ошибки, не содержащие пользовательский текст, также могут отображаться overlay: нет последнего слова, выделение отсутствует, раскладка недоступна или приложение не разрешает AX-замену.

## Что намеренно не исправляется

- mixed-script слово вроде `приvet`;
- Enter/Tab boundary;
- URL, email, путь или программный identifier;
- ввод в password manager, Secure Input или AX secure field;
- слово после клика, навигации или смены frontmost app;
- раскладка вне выбранной пары;
- приложение из пользовательского исключения.

## Устранение неполадок

### Нет значка в menu bar

Проверить Activity Monitor, завершить старый процесс и снова открыть `.app`. Dock-иконки у приложения нет по дизайну.

### Автокоррекция не работает

Проверить:

1. master switch и автоисправление;
2. оба системных разрешения;
3. выбранные English/Russian input sources;
4. что приложение не находится в исключениях;
5. что Secure Input выключен;
6. перезапуск монитора на вкладке «Приватность».

### После пересборки разрешения пропали

Ad-hoc подпись может изменить code identity. Удалить старую запись Lang Switcher из Accessibility/Input Monitoring, добавить новую `.app` и перезапустить процесс. Стабильный Developer ID уменьшит такие случаи.

### Хоткей не срабатывает

Выбрать другой пресет: комбинация может быть занята macOS, Spotlight, менеджером окон или другим приложением. `⌥Space` часто используется для неразрывного пробела внутри редакторов, но зарегистрированный global hotkey перехватывает его; выбирайте этот пресет только если такое поведение желательно.

### Выделение не преобразуется

Убедиться, что поле редактируемое и приложение предоставляет AX selected text. PDF, canvas, терминальный псевдоэкран или нестандартный web editor могут не поддержать этот путь.

## Удаление

1. Выключить «Запускать при входе».
2. Завершить Lang Switcher.
3. Удалить `.app`.
4. Отозвать Accessibility/Input Monitoring.
5. При необходимости удалить настройки: `defaults delete local.lang-switcher.app`.
